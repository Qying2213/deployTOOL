# 主项目后端测试服发布耗时优化说明

更新日期：2026-09-21

## 问题证据

2026-09-20 的一次主后端测试服发布从开始合并到最终恢复约耗时 27 分 26 秒。其中可重复的两个明显耗时点是：

1. 同一个精确提交在首次发布失败后，重试时再次执行完整 Ruff、迁移影子库和全量 pytest，单次约 2 分 13 秒。
2. 服务器每个 release 都创建独立虚拟环境，原实现还会重新解析整棵依赖图；当次 `uv` 仅解析 68 个包就耗时 58.96 秒。

另外，旧输出没有统一阶段耗时，很难立即区分卡在本地测试、SSH、上传、依赖安装、迁移还是通知验收。

## 本次改进

### 1. 每个阶段输出独立耗时

`deploy-test-backend` 和主后端发布器现在都输出阶段开始、阶段完成或阶段失败及耗时，并在成功或失败时输出总耗时。可直接定位：

- Git 同步、状态检查、环境审计和 dry-run；
- Ruff、迁移影子库、pytest；
- 远端 preflight、本地打包、staging、上传；
- 依赖安装、数据库迁移、版本激活和通知验收。

### 2. 精确锁定依赖，不再反复求解依赖图

新 helper 协议版本为 `7`。服务器仍然为每个 release 新建独立 `.venv`，但改为：

1. 从已审核的 `runtime-constraints.txt` 逐项安装精确版本，禁止再递归求解依赖；
2. 以 `--no-deps --no-build-isolation` 安装当前后端包；
3. 在停止任何 writer 之前执行 `uv pip check`，依赖缺失或版本不兼容就立即失败，保留旧版本运行。

这不是共享或复制旧版 `.venv`；新旧版本仍完全隔离，回滚边界不变。

### 3. 测试服的精确门禁回执

测试服首次真实发布仍完整执行 Ruff、迁移闭环和全量 pytest。全部通过且二次校验没有发生变化后，在 Git 忽略的 `dist/backend-gate-receipts/` 中原子写入 `0600` 回执。

只有同时精确匹配以下条件，且未超过 6 小时，测试服的失败重试或受控 `recover` 才可以复用：

- 环境必须是 `test`，分支必须仍是 `test`；
- 完整 Git commit；
- 唯一 Alembic head；
- 运行时依赖清单 SHA256；
- Python 解释器版本、路径及已安装包集合的指纹；
- 本地数据库门禁等相关环境变量与 `.env` 内容的脱敏 SHA256 指纹；
- 门禁合同版本和固定 6 小时有效期。

复用时仍会再次检查干净工作树、upstream、commit、Alembic head、依赖指纹和 `git diff --check`。任何一项不匹配都会自动回到完整门禁。

正式服从代码和回执校验两层都禁止复用，仍每次完整执行所有门禁。

## 没有改变的安全边界

- 不提供真实发布跳过测试的参数。
- 不减少产物哈希、CAS、发布锁、备份、迁移、schema 校验、原子切换或健康检查。
- 迁移尝试后的失败仍保持停写，不自动 downgrade 或恢复数据库。
- 依赖安装仍由无登录权限的独立构建用户执行，最终 runtime 仍归 root 所有。
- 本次不自动删除服务器历史 release，避免在未确认保留策略前扩大变更范围。

## 预期效果与验收

- 正常发布：预期消除已精确锁定的 68 个依赖的大部分重复求解时间；具体节省值需在 helper 7 第一次真实发布后以阶段日志确认。
- 同提交失败重试：在六小时精确匹配窗口内，预期避免再次消耗约 2 分 13 秒的完整门禁。
- 可观测性：后续无需凭感觉判断“卡住”，可直接从阶段耗时定位。

合并本改动后，先对测试服显式执行 helper 7 的安全同步，再做一次 dry-run 和一次真实测试发布。正式服 helper 不随本次代码改动自动升级，必须单独审核、备份和安装。

## 本次未执行的事项

本轮只修改部署工具代码、测试和文档；没有同步服务器 helper，没有发布业务代码，没有迁移、重启或写入数据库。

- 主后端发布与一键脚本专项：40 passed。
- Node 语法、两个 Bash 脚本语法和 `git diff --check` 全部通过。
- 当前本地 Python 环境 `pip check` 通过；项目 16 个直接运行时依赖全部存在于 70 项精确锁定清单中。
